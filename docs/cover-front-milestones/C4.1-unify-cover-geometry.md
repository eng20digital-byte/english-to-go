# C4.1 — Unify cover geometry + fix closed sizing

> First of the three-part [C4](./C4-cover-open-rework.md) fix set. Sizing fix
> only — animation choreography is unchanged here (still combined; C4.2 sequences
> it).

## Goal

Stop the centered closed cover from rendering too large / clipping at the bottom.
Make the closed cover **the clipped right-half of the same flex box the open book
uses**, so it matches the open book's right page by construction. Keep the
thick-book chrome (right fore-edge stack + left binding shadow), resized to the
new dimensions. No visible animation change (open/close still play exactly as
they do today).

## Root cause

`BookCover`'s closed layout
([BookCover.tsx](../../src/reader/BookCover.tsx) `'closed'` branch) sizes itself
`height: min(100vh - 40px, COVER_CANVAS_HEIGHT)` + `aspectRatio 960/1080` with
**no width bound**. The open book is `flex:1` + `maxWidth: min(READER_MAX_WIDTH,
(100vh-40) * SPREAD_ASPECT)`, so on non-16:9 viewports it is *width-bound* and its
half-page is shorter than `100vh-40`. The closed cover therefore renders larger
than the open book's real half-page (and past the bottom). The only robust fix is
to size the cover the same way the open book does — which means letting flexbox
resolve the full-spread width and showing the right half.

## Exact changes

### BookCover — collapse to one tree, closed = held first frame

Merge the two return branches (`'closed'` vs animating) into **one JSX tree** that
differs only by className / inline style. This both fixes sizing and sets up the
seamless `closed → opening` handoff (in-place reconcile, no remount flash).

- **Outer box** (root for all states):
  `position: relative; flex: 1; maxWidth: min(${READER_MAX_WIDTH}px, calc((100vh -
  40px) * ${SPREAD_ASPECT}))` — identical to the open-book wrapper in
  ReaderBookletPage. In `'closed'` state attach the existing tap/swipe-to-open
  handlers (`role="button"`, `aria-label="Open booklet"`, `cursor: pointer`,
  `touchAction: 'pan-y'`, `handlePointerDown`/`handlePointerUp`). Do **not** attach
  them while animating (can't interrupt mid-open).
- **Card** (`cardRef`): `position: relative; width: 100%; aspectRatio: 1920/1080;
  perspective; boxShadow` — the existing animating card. The **closed framing** is
  the held first frame of `book-cover-expand`, applied as inline style:
  `clipPath: 'inset(0 0 0 50%)'` + `transform: 'translateX(-25%)'`. That places the
  cover (the leaf front face) centered at box `[25%..75%]`, exactly half-page-sized.
- **Card contents are identical in every state**: base `<PageCanvas
  page={firstSpread} …/>` (full spread, hidden behind the clip/leaf while closed),
  the permanent `.book-spine`, and the leaf with its two faces (front = cover at
  `COVER_CANVAS_WIDTH/HEIGHT`, back = spread 0's left half). **While closed the leaf
  carries no animation modifier** — class `.page-flip-sheet` only (no
  `--next`/`--prev`), so it rests flat at `rotateY(0)` showing the cover and does
  **not** auto-run a flip on mount.
- **Scale**: one basis for all states — `useCanvasScale(cardRef, CANVAS_WIDTH)`
  (the card is always the full spread now). Drop the
  `isAnimating ? CANVAS_WIDTH : COVER_CANVAS_WIDTH` branch and its comment.

### BookCover — thick-book chrome, repositioned (closed state only)

The card is clipped to its right half, so chrome **cannot** live inside it (the
clip would remove it). Render the chrome as **siblings of the card in the outer
(unclipped) box**, only when `coverState === 'closed'`, positioned at the visible
cover's edges:

- **Right fore-edge stack** — reuse `.book-edge.book-edge--right`, `position:
  absolute; left: 75%; top: 0; bottom: 0; width: spreadCount *
  BOOK_SHEET_THICKNESS_PX` + the `--book-sheet-thickness` var. (Visible cover's
  right edge is box `75%`.)
- **Left binding shadow** — reuse `.book-cover-spine`, `position: absolute; left:
  25%; top: 0; bottom: 0` over the card (`pointer-events:none`, so tap/swipe still
  fires). (Visible cover's left edge is box `25%`.) If it visibly doubles with the
  clipped `.book-spine`, drop the in-card `.book-spine` for the closed frame only.

During `'opening'`/`'closing'` the chrome is **not** rendered (matches today's
animating layout; the open book re-supplies its own `.book-edge` stacks). The
brief pop at handoff is the existing behaviour, unchanged.

### index.css

No keyframe changes in this milestone — `book-cover-expand` / `book-cover-collapse`
still drive the (still combined) animation. Only confirm `.book-edge--right` /
`.book-cover-spine` render correctly when positioned by `left:%` in the outer box
(they're `#reader-root`-scoped, geometry comes from inline style — no rule change
expected).

## Manual verification

1. **Closed cover sizing** — open a published booklet that has a cover (`/b/:token`).
   The centered cover is **fully visible (no bottom clip)** and the **same size as
   the open book's right page**. Test specifically on a **non-16:9 window**: resize
   the browser taller/narrower (e.g. 16:10, or a tall portrait window) and confirm
   the cover no longer overflows and tracks the open book's page height.
2. **Thick-book look** — the right fore-edge page-stack and the left binding shadow
   are present and hug the resized cover's edges.
3. **Open / close still work** — click / tap / ArrowRight / Enter opens (animation
   plays as before for now); prev / ArrowLeft / swipe-right at spread 0 re-closes;
   handoff to/from PageFlip at spread 0 has no scale jump or seam.
4. **Reduced motion** — instant open/close still lands on the correctly-sized
   centered cover.
5. **No-cover booklet** — unchanged; opens straight to spread 0. `npm run lint` +
   `npm run build` (tsc) clean.
